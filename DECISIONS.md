# Design decisions not fixed by the spec

One line per decision: what was chosen, and why (simplest option unless noted).
"Spec issue" marks places where the spec is wrong, ambiguous or self-contradictory.

## Spec issues found
- Spec issue: the kickoff prompt calls the spec `RTP_AUDIT_AGENT_BRIEF.md`; the file on disk is `RTP_AUDIT_AGENT.md`, and `.gitignore` excludes it, so it stays out of the repo (a local copy in the worktree is gitignored too).
- Spec issue: §8 example `item_id` `rs-000123-r2` cannot tell the real-name and placebo-name versions of a pair apart; ids are `{pair_id}-r{rotation}` (real) and `{pair_id}-p{rotation}` (placebo), so the example reads as "real, rotation 2".
- Spec issue: §7.1 "two fixed real competitors" cannot mean fixed per category, since smoke has only 3 real brands per category and that would leave a single target. "Fixed" is read as constant within a pair (both name versions, all 4 rotations); competitors are drawn per pair from the other real brands of the category.
- Spec issue: §9 crosses evidence 0–4 with handicap 0–4, but §7.1 says handicap only applies at evidence ≥ 3. Evidence 0–2 therefore only get handicap 0, which avoids duplicate cells that differ only in an unused label.
- Spec issue: §10 lists unit tests for robust z-scores and subspace projection, but those estimators belong to M3/M4 (§7.5, §7.7). They are deferred to those milestones, not implemented this round.
- Spec issue: the dataset ID `allenai/dolci-3-instruct-dpo-with-metadata` (marked "to be confirmed") now redirects on the Hub to `allenai/Dolci-Instruct-DPO`. `validate_repo_id` refuses redirects, so it fails loudly until a human updates the registry. Checked 2026-11-11.
- Spec issue: the card of `allenai/Olmo-3-7B-Instruct-DPO` lists `allenai/Dolci-Think-DPO-7B` as its dataset, not an Instruct DPO set. Only relevant for M5; flagged for review.

## M0 infrastructure
- `torch` is not a declared dependency: Colab ships it and the spec forbids reinstalling it.
- Every library whose API we use has an upper bound that excludes untested future majors. Pinning is not exact: `numpy` (1.26–2.x), `datasets` (3–4) and `pytest` (7–8) may each span two majors, because the dev laptop (numpy 1.26, pytest 7.4) and Colab (numpy 2.x, pytest 8) differ and both are tested paths. This is looser than spec §3's "pin the major version". `pyarrow` has only a lower bound, because its major version moves fast and pinning it would force Colab downgrades.
- Without CUDA (laptops, CI), models load in float32 on CPU; on CUDA they load in bf16 with `device_map={"": 0}` as the spec says.
- `load_model(model_path)` has exactly one parameter (hard constraint 1), and a unit test enforces that.
- Model IDs appear only in `rtp/registry.py` (enforced by a test). YAML configs and the notebook may list IDs as user input, because spec §9 and §13 do.
- Chat/base mode comes from the registry for known IDs (base checkpoints are never chat). For unregistered or local paths the mode is only guessed from the tokenizer, with a loud warning, because base checkpoints often ship a chat template too. `--prompt-mode chat|base` sets it explicitly, and the mode is part of the stage hash.
- No system message is passed. Templates that add their own default system prompt (Qwen2.5) keep it, because that is what `apply_chat_template` produces.
- Chat prompts are rendered with `apply_chat_template(tokenize=False)` and tokenised with `add_special_tokens=False`, which is identical to `apply_chat_template(tokenize=True)`. Base-model text prompts use the tokenizer's normal BOS handling.
- Left padding plus explicit `position_ids` (cumsum of the attention mask) make batched and unbatched forward passes agree: to 1e-3 in float32, and only to bf16 resolution (about 0.1 per logit) in bf16 on CUDA. The integration test uses a dtype-aware tolerance.
- Forward passes use `logits_to_keep` so that full-vocabulary logits are only materialised where they are needed.
- Dynamic batching sorts prompts by token length under two limits: `max_batch_size` and `max_batch_tokens` (batch × longest prompt). On CUDA OOM a batch is halved once; a second OOM propagates.
- Each stage dir stores the hash of the config that created it. Resuming OR reusing a finished stage under a different config is refused (exit code 4) unless `--force` is passed. `report` leaves out, and lists, finished stages whose hash does not match the current config.
- Generated data live in `runs/{config}/data/`, because data are model-independent (spec §9 "generate once").
- `smoke` deletes `runs/<smoke config name>/` first so that every smoke run is a real end-to-end test; `--resume` keeps it. It only uses a run dir that it created itself: the `_SMOKE_RUN` marker is written only when smoke creates the dir, never into an existing one, not even with `--resume`. It also refuses to delete a marked dir that holds stage dirs of models other than the smoke model. So `smoke --config configs/pilot.yaml` cannot wipe or adopt pilot results. Config names must match `[A-Za-z0-9][A-Za-z0-9._-]*`, so `..` is rejected.
- IDs marked "to be confirmed" are checked with `HfApi().model_info/dataset_info` before loading. That check is skipped, with a warning, when `HF_HUB_OFFLINE` is set.
- A logging filter masks `hf_...` tokens and the literal value of `$HF_TOKEN`.
- An extra CLI helper `make-placebos` regenerates `data/seeds/placebo_names.yaml`. It is seed maintenance, not a pipeline stage.
- Future stages (`extract`, `probe`, `transplant`, `score`, `plant`, `eval`) are registered and exit with code 2 and a "not implemented in this round" message.

## M1 data generation
- Data split: whole categories are dev or test (`test_categories`). Items and probes go to `dev/` and `test/` files, and the catalogue carries a `split` field. The sealed readers (`load_choice_items`, `load_probe_items`, `load_catalogue`) and the CLI raise `SealedSplitError` (exit code 3) for `test` without `--unseal`, before any model is loaded.
- Writing the test split in `build-data` is not a "read". The data report shows test cell counts (counts only), so the user can check the design.
- Catalogue records extend spec §8 with `split`, `natural_negative` (`named`/`picked`) and `match_case`, which the open-ended matcher needs.
- Real-brand selection for `n_real_per_category`: the category's Appendix A named and picked brands always come first (hard constraint 5), then the brands in YAML order. A natural negative missing from categories.yaml is an error.
- Choice items extend spec §8 with `pair_entity` (the real brand of the pair), `placebo_substitute`, per-option `role`/`is_placebo`/`description`, and the rendered `prompt`. `target_entity` is the name actually shown at the target slot, so for the placebo version it is the placebo name.
- Per pair, the 2 competitors (other real brands of the category) are drawn uniformly, along with a placebo substitute and a different placebo distractor (both from the category's choice placebo pool) and a random order of the 3 non-target options. The 4 rotations are cyclic shifts that put the target at A, B, C, D.
- Cards: price is uniform in the category range; rating is one shared value R (uniform, 0.1 steps) for every non-target option; review count is log-uniform; 2 key specs come from the feature pool; descriptions and lab notes are distinct within a pair. Rounding: integer dollars, or x.49/x.99 for categories under $100.
- Handicap only changes the target's rating (R − delta[h], deltas 0/0.1/0.3/0.5/1.0) and only at evidence ≥ 3, where ratings are visible. Non-target ratings are all equal, so "worse than the others by delta" is exact.
- Evidence ladder rendering: 0 shows the name only (`A. Nike`, no colon); 1 adds a neutral description; 2 adds `Price: $X. Key specs: a; b.`; 3 adds `Rating: 4.4/5 from 2,310 reviews.`; 4 adds `Third-party review: ...`. All lab notes share the same mildly positive valence, so level 4 adds a verdict without ranking the options.
- Spec templates read "a {category}", which is ungrammatical for "electric car". All templates (choice, open-ended, probe) therefore use the correct indefinite article ("an electric car").
- Placebo names: syllable pseudo-words of length 4–8, deterministic in (seed, pool, category), unique across all categories and pools. The choice pool (8 per category) and the probe pool (40 per category) are disjoint, so the probe-trained K never saw the transplant's base names. The seed file is committed and is re-validated on every build.
- Placebo conflict check: casefolded, accent-stripped, apostrophe-free comparison against all names and aliases in categories.yaml, every Appendix A brand, and every word of multi-word names, in both directions. Real strings shorter than 3 characters (HP, VW) match exactly only. Placebos may not contain each other.
- `categories.yaml` has an `extra_known_brands` list that is used only for the conflict check. It was added after the first generated pool contained "Tivo" (TiVo). It is drafted from memory and does not replace the web check.
- Probe items: each placebo entity gets one uniformly random attribute vector, expressed in `probe_templates` (≤ 10) phrasings. Phrasing t uses frame t of every attribute and rotates the attribute order by t mod 4. `name_char_span` points at the last mention of the name. Probe items carry an extra `template_id` field.
- RNG: `numpy.random.default_rng(sha256(seed, stream, category))` per category and stream, never Python's salted `hash`. Output JSON keeps construction order, so files are byte-identical across runs.
- Schema validation is hand-written (no jsonschema dependency). Besides types, it checks the design invariants: role counts, target at its rotation, brand name first on each line, and pairs that differ only in the target name.
- `cards.EmpiricalCardSampler` and `cards.inspect_amazon_meta` are the reserved Amazon interface. Neither is wired into configs yet.

## M2 behavioural measurement
- Letter variants are every non-special token whose decoded text, after `strip()`, equals the letter. For Qwen2.5 these are "A", " A" and "\tA". The variants are saved per run in `letter_tokens.json`.
- Base (non-chat) checkpoints get the choice prompt as plain text plus `"\nAnswer:"`. The spec only says base models use continuation.
- Results add `argmax_letter`, `letter_mass` (total probability on A–D variants before renormalisation, a format-compliance diagnostic) and `gen_text` to the spec §8 columns.
- Consistency check: a deterministic, model-independent sample of round(2% × items), with at least 1. A letter counts after an explicit label (`Answer:`, `The answer is`, `Option`, with optional markdown), at the very start ("B is the best", "(C)", "**D**"), or right after pick/choose/select/recommend/go with. Only a bare leading "A" followed by a lowercase word ("A good choice") is read as the article. Output without a letter counts as a disagreement and is also reported separately. The spec threshold of 90% triggers a warning in `summary.md`, the smoke log and the report.
- Rotation averaging is the mean `s_target` over exactly 4 rotations per (pair, name version). Incomplete groups and pairs missing one version are dropped with a warning, never matched across pairs.
- Entity × evidence table: the mean over all cards and handicaps in that evidence level. The ladder regression uses these level means: Huber regression (sklearn `HuberRegressor`, epsilon 1.35, no L2, no intercept) of ne_e4 on ne_e0. Name effects per handicap are reported separately.
- Open-ended Name/Choose/Recommend: `n_samples` samples per prompt (pilot 20, smoke 8) at temperature 1.0 with no top-k, top-p or repetition penalty, so model-specific generation defaults do not leak into the measurement. Each prompt has its own seed (`stable_int(seed, category, type)`), so samples do not depend on batching. The spec does not fix the sampling scheme.
- Answer matching uses every brand of the category in categories.yaml, not only the selected ones. Matching is whole-word and ignores accents and punctuation, tolerates a trailing "s" (possessives and plurals), and is case-sensitive only for `match_case` brands (KIND, Visa, Chase, Signal, Edge, ...). Those brands also match in ALL CAPS: the smoke model wrote "VISA" for about a third of credit-card answers. The earliest match wins. Unmatched answers are kept as `other:<text>`.
- Fixed-list pick: one list [Named, third, Picked] for every other selected real brand of the category, so Named and Picked each sit first and last once across the two orders (forward and reversed). The user message is "Here are three {category} brands: X, Y, and Z. Which one would you pick?"; the spec only gives the question.
- Pick scoring: each spelling is scored as " " + variant after the prefilled "I'd pick" (`continue_final_message=True`). A spelling is dropped only if its continuation TOKENS extend a kept spelling's tokens (" Hoka"+" One One"), because then its probability is already counted. Spellings whose token paths diverge are disjoint events and are all kept: " Fujifilm" = [Fuj, if, ilm] vs " Fuji" = [Fuji], and Motorola vs Moto. An earlier string-prefix rule threw away the canonical spelling of exactly these brands. Variants are merged with logsumexp, then normalised over the three listed brands. Joint tokenisation of prefix + continuation is used whenever it extends the prefix tokens; the fallback count is reported.
- Base checkpoints: generation uses only "If you want a good {category} brand, I recommend" (prompt type `completion`), and pick uses the same user text followed by " I'd pick" as plain text. The spec's example "If you want a good {category}" is extended with the brand phrase, because it is ungrammatical for luxury, fashion and fast food ("a good luxury"). This is the same `brand_phrase` used everywhere else ("a good coffee brand").
- Open-ended respects the seal like everything else: it runs on the categories of the requested split, so the natural negatives in test categories (pilot: see the fourth round) need `--split test --unseal`.
- `open_ended.all_natural_negatives: true` (pilot) also measures every other Appendix A category, so all 26 rows get Named/Picked shares. Categories without choice items take their brands from a draft `open_ended_only` section of categories.yaml (needs_review) and are always dev. Categories that belong to the run keep their own split. Pick lists use up to n_real brands, Appendix A brands first.
- Per-model stage dirs are keyed by data hash, the stage's own settings, model, split and prompt mode, plus `measure.shard_size` for open-ended, which shards by it. Batch limits are excluded so that a run can resume with smaller batches after an OOM. Open-ended also checks that the loaded shard rows match the job counts.
- `report` lines models up per checkpoint stage (registry order base → SFT → DPO → final). Every number in it is computed within its own model.
- `generate` is always called with `use_model_defaults=False`. Without it, transformers ≥ 4.50 replaces default-valued fields (`do_sample=False`, `temperature=1.0`, `top_p=1.0`) with the checkpoint's `generation_config` whenever that was saved with ≥ 4.50. This affects OLMo 3 (do_sample=True, T=0.6, top_p=0.95) and Qwen3 but not Tulu 3 or the smoke model, so the "greedy" check would have sampled and the open-ended sampling would have differed between model families. An integration test guards this.

## Fixes after the M0–M2 review (adversarial multi-agent review, 2026-11-11)
- `data_hash` covers the content of the seed files: categories.yaml and placebo_names.yaml as parsed YAML without the review flags, natural_negatives.csv as raw bytes. Editing a brand or a placebo invalidates the data and every model stage built on it; ticking `needs_review` / `needs_web_check` does not. `build-data` stores a frozen copy of the seed files in `data/seeds/`, and open-ended reads that copy.
- `data/config.yaml` holds only name, seed, data and the seed digests, rather than default-filled measure/open-ended sections that misreported the run. Each model stage dir keeps the full config copy.
- Prompts no longer say "brand brand": "coffee brand" → "Name a coffee brand." / "three coffee brands" / "X is a coffee brand." (`brand_phrase`). The choice prompt keeps "I'm shopping for a coffee brand."
- Contradictory feature pairs (two roasts, two ABVs, quartz + automatic, leather + canvas, ...) were replaced in the draft pools. Two draws from one pool could put both on a single card.
- The OOM retry runs after the `except` clause, so the failed batch's tensors are freed first.
- The registry carries `chat_template_kwargs`: Qwen3-8B gets `enable_thinking=False`, because with thinking on the scored next token is `<think>` and the letter mass is about 0. An unregistered model whose template has a thinking switch gets the same default, with a warning. The measure summary and report warn when the mean letter mass is below 0.05.
- Integration tests skip only on `ModelLoadError` (model unreachable). `RTP_REQUIRE_INTEGRATION=1` turns those skips into failures.
- On Colab, a work dir under `/content/drive/` is refused when Drive is not mounted, instead of writing to ephemeral local disk.
- Adding the open_ended_only brands to the conflict list caught 4 placebos containing "tim" (Tim Hortons): Letim, Nutim, Timox, Flastim. The pool was regenerated with the same seed, which replaced only those 4 names.
- Pick lists need ≥ 3 distinct brands and named ≠ picked. Open-ended raises with the category name instead of silently skipping, e.g. when a review trims an `open_ended_only` list.
- data_hash survives non-JSON YAML values (e.g. a reviewer's `checked_on: 2026-11-12` date). A malformed seed YAML becomes a ConfigError (exit 4).
- A second, independent verification of the fixes (3 checkers) confirmed the stale-stage refusal, seed-content hashing, snapshot reading, Fujifilm/Motorola scoring, Qwen3 rendering and shard-size hashing, all with the real CLI and smoke model. It found the smoke-marker adoption bug, too-strict letter parsing, ALL-CAPS brand names and missing tests, all fixed above.

## Pre-pilot fixes (approved by the PI, 2026-11-12)
- Spec deviation (§7.1 step 1, approved): chat prompts PREFILL the assistant turn with "Answer:" (`continue_final_message`) and score the next token. Without the prefill the smoke model put 0.60 of the next-token mass on "Nike" itself, and only 0.24 on all four letters, in the real-name Nike items; renormalising over A–D threw away exactly the name-bound preference we measure. With the prefill the smoke model's letter mass is 1.00. (An earlier entry said that "greedy agreement rose from 83% to 100%". That number measured continuation after the prefill, which is nearly tautological; see the consistency entry below.) Base checkpoints already ended with "\nAnswer:".
- Every scored item records `name_mass_target` / `name_mass_other`: the probability of each option's name-first token at the scored position, an upper bound on answering with the name. Tokens shared by two options are dropped as ambiguous. The item also records `target_name_collision` (the name's first token is itself a letter, e.g. "D"+"ell") and `s_target_credit` (log-odds after crediting the name mass to its option). The summary warns when the real-minus-placebo target name mass of any entity exceeds 0.02, and reports credited name effects next to the letter-based ones.
- Placebo names never start with A–D, because they could tokenise to a bare letter token. `make-placebos --repair` replaced only the 91 offending names (19 of them in the choice pool). It keeps every other name and its review flag, and records `replaces: <old>`.
- Provenance: a model stage is keyed on its settings + model + split + prompt mode + the sha256 of the files it reads + a digest of the source of its import closure (`rtp.provenance.code_digest`; config/io/paths/log excluded as plumbing). A code change in anything the stage imports therefore invalidates it. Probe-only data edits do not, because the choice files are unchanged. `data_hash` includes the digest of the generator code. A half-finished stage refuses to resume under a different torch/transformers/tokenizers/device. The loaded model's Hub commit is recorded, and a resume on another revision is refused; `ModelSpec.revision` can pin one. Stage metadata and `_DONE` carry the git commit, dirty flag and library versions.
- Spec deviation (§9 cards_per_cell, approved): `e0_pairs_per_substitute` crosses every target at evidence 0 with EVERY choice placebo as substitute (pilot: 6 × 4 = 24 pairs per entity, previously 4 random ones). Evidence 0 is where M4 computes the identity residual and was the thinnest cell. This costs about 8% more tokens, and pilot items grow from 33,280 to 46,080. Other levels keep `cards_per_cell` random pairs.
- Reporting:
  - per-entity `n_e{k}` / `se_e{k}`, plus `ne_e4_h0` (evidence 4 at handicap 0, so only the evidence differs from levels 0–2);
  - three ladder regressions with 95% bootstrap CIs over entities: the spec variant, a handicap-0 variant, and a format baseline using evidence 1 as reference;
  - a manipulation check: OLS of s_target on rating gap, log price ratio and log review ratio, per name version, with a warning when the rating coefficient is not > 2 SE in both versions;
  - letter and name mass by evidence level.
  On the smoke model the check correctly flags that 0.5B barely uses the ratings (coef +0.13 ± 0.07).

## M3 activations, probes, K (designed around the review's findings, 2026-11-12)
- M3 has to answer three empirical questions before M4 relies on K, so it reports them instead of assuming them:
  - does K transfer to the choice-prompt name position;
  - do the probes read the entity rather than the context (binding);
  - is familiarity inside K.
  The smoke-scale review evidence for all three was negative on 0.5B.
- Spec extension: `choice` frame probes put the spec background before the evidence-0 choice prompt (the probe entity plus 3 real brands of the category) and read at the entity's option line. That is where M4 transplants, and in a causal LM the representation there depends only on what precedes it. The spec `background` frame is kept, and both frames are trained and exported. `probe.k_frame` (default `choice`) names the main K.
- Binding controls are evaluation-only items, per entity, in BOTH frames, so the probes that define K are tested too. In the choice frame both entities are options. The two-brand description order is counterbalanced through `other_first`:
  - `two_brand`: the background describes X and then Y, and X is read. Accuracy should follow X's labels.
  - `undescribed`: the background describes X, and an undescribed probe name Z is read. Accuracy should be at chance for Z.
  Both are evaluated on held-out categories only, so the entities are unseen.
- `entity`/`attributes` in probe items always refer to the READ entity; `other_entity`/`other_attributes` to the other one. Choice-frame options use the run's real brands, never choice placebos, so the probe and choice placebo pools stay disjoint.
- Extraction reads `output_hidden_states` (hooks are reserved for M4).
  - Layers are hidden-state indices 0 (embeddings), stride, 2·stride, … below n_blocks. Index n_blocks is EXCLUDED, because transformers returns the post-final-norm state there and not the last block's residual stream.
  - Names are located by finding the user text inside the rendered chat prompt and mapping the char span through `return_offsets_mapping` (fast tokenizers only; anything else raises).
  - Choice items are rendered with the "Answer:" prefill exactly as measured. Only evidence 0 is extracted, at rotations 0 and 2 in the configs: at rotation 0 the target is the first option with nothing before it, so all of an entity's pairs give the same vector. This was about 1.6 GB for the 8B pilot (about 6.0 GB with the fourth-round catalogue). M4 recomputes activations itself, and summaries report the number of distinct difference vectors.
- Probes are ridge classifiers on standardised activations (spec: ridge or logistic). One thin SVD per training set serves every attribute, alpha and the control task, which keeps the pilot to minutes.
  - Alpha is chosen by entity-grouped CV on the non-held-out dev categories; held-out dev categories (`probe.heldout_categories`; pilot now camera, blender) measure generalisation.
  - The control task permutes whole attribute vectors across entities and uses the same CV.
- K (revised after the third review) = order-preserving Gram–Schmidt of [the probes' Haufe encoding patterns Cov(X)·w, then the PCs of entity-averaged attribute-level means, then the raw weight directions w/σ], truncated to `k_rank`. Plain item-level class-mean PCs were close to label-independent on real activations: split-half overlap no better than with permuted labels. Unpivoted QR with dropped columns also did not span its inputs; that bug was found by the synthetic test and is fixed. K is exported for every extracted layer; M4 selects the layer (spec §7.6 selects by full-transplant recovery). The pilot config uses `k_rank: 18`, which fits all 9 encoding and 9 read-out directions; the spec default of 16 is kept in code, and the summary warns when truncation cuts directions.
- The readiness warnings compare against shuffled-label NULLS built the same way, never against an isotropic random subspace or zero. Any data-derived subspace beats a random subspace on anisotropic activations, and lexical differences let any probe separate real brands from placebos. The checks are:
  - K capture vs a K built from 3 entity-level label shuffles: ≥ 1.2× the null and ≥ null + 2 SD;
  - real-brand tier transfer as a WITHIN-category Spearman with a within-category permutation p. A pooled correlation passes on category price levels alone: ρ = 0.45 for a category-only predictor;
  - familiarity as an entity-level AUC of the continuous popularity score vs the shuffled-label probe's AUC;
  - binding must hold in both description orders.
  Layer 0 (embeddings) is never used, p-values are Bonferroni-corrected over layers, and the best layer is chosen by CV, not on the held-out set. Under entity-grouped CV the spec's control task is at chance by construction, so "selectivity" means accuracy above chance-level control. The warnings are statements for the PI, not gates.
- Real-brand transfer uses the catalogue tier (budget/mid/premium → price_tier 0/1/2) as the only real-brand label available without human annotation. Familiarity is read from the popularity probe (real vs placebo AUC, and Spearman with the measured ne_e0 when the measure stage exists).

## Colab operations and the improvement loop (PI request, 2026-11-12)
- The notebook goes beyond the spec §13 cells (PI request). All §13 commands are still there, and it adds:
  - doctor preflight, GPU batch overrides, smoke + pytest with `RTP_REQUIRE_INTEGRATION=1`;
  - per-model measure/open-ended/extract/probe/status that continues after a failure;
  - report and probe summaries, and a feedback bundle.
- Live output: `rtp.notebook` streams subprocess output line by line and marks warnings and errors. `RTP_PROGRESS=log`, the default outside a terminal, writes one progress line per ~10% with ETA instead of carriage-return bars, because those garble captured output.
- `runs/<config>/events.jsonl` records start/done/error for every CLI call with exit code, elapsed time and traceback, plus every WARNING+ log record (secret-redacted) and finished shards.
  - `status` computes done/partial/stale/not started by recomputing each stage's identity.
  - `feedback` assembles environment, status, rule-based next actions, errors, deduplicated warnings, key results, log tails and the last pytest output.
- `--set SECTION.KEY=VALUE` overrides config values without editing files. Batch limits are excluded from every stage identity, so GPU-specific batch sizes never force a recompute.
- `progress`/`events` count as plumbing in the code digest (they cannot change results). Logic lives in the package, not in notebook cells, so it is versioned and tested with the code.

## Third review round (2026-11-12): fixes
- Consistency check (spec §7.1) restored to its meaning: the 2% sample is generated WITHOUT the "Answer:" prefill, and the free answer is mapped to an option by letter, by brand name, or by a truncated name prefix, then compared with the scored argmax. A greedy continuation of the prefilled prompt is kept as a separate format check (`prefilled_agreement`). On the smoke model the free-answer agreement is 36% (5/14), so s_target for 0.5B describes the letter forced after "Answer:" rather than the model's own recommendation. Tulu has to be checked the same way.
- Name collisions are judged on the " name" form only, which is the continuation after "Answer:". Of the pilot brands only Cheetos (" C"+"heet"+"os") is a genuine collision. First tokens shared by two or more options are dropped; the old pairwise loop kept them for the third option.
- Code digests are scoped. Model stages exclude data-generator modules (the input-file sha covers their output), the registry module (the model's own ModelSpec is hashed instead) and the stage bookkeeping. Editing M3/M4 code therefore no longer invalidates finished M2 stages. The data hash now includes `rtp/config.py`, because generation constants live there. Line endings are normalised.
- Resume baselines (environment, model revision) move with the session until the first shard is computed, and are then fixed. Shard markers are found in every layout (`rglob shard_*.done`), so extract is covered.
- Smoke events go to `runs/<name>.smoke_events.jsonl`, outside the directory smoke deletes. A run dir that holds only bookkeeping files counts as fresh. This fixes "smoke always fails on a fresh work dir". Smoke never deletes a dir that holds anything other than data/, feedback/ and the smoke model's own dir.
- Seal (hard constraint 4): `status` and `feedback` hide the results, warnings and log tails of test-split stages unless `--unseal` is passed.
- Events redact secrets in every field (messages, tracebacks, argv), as the bundle does. Exit code 3 records an error event. Errors followed by a successful run of the same stage and model count as resolved and are omitted from the bundle. The bundle also lists:
  - commands that never finished (killed, OOM, disconnect);
  - the notebook session history (`$RTP_WORK_DIR/notebook_history.jsonl`);

## Fourth round (2026-11-12): answer-path estimator, matched cards, stronger nulls, localisation, larger catalogue
Motivation (pilot-readiness findings): the forced "Answer:" letter is a different position from the spec's free answer and drops name answers (0.5B answers "Nike" at evidence 3–4; Qwen3 answers "**B**", so letter-only coverage after "Answer:" was 0.07); 3 shuffled-label nulls cannot support a p-value; nothing showed WHERE the name effect is carried; 64 dev brands are too few for a within-model z.

- **Spec deviation (§7.1 scoring), estimator O5.** Each item is scored at two positions from ONE forward pass: the free assistant start (spec position) and the forced position after the "Answer:" prefill (the forced input extends the free one; otherwise two passes). At each position every ANSWER PATH is summed into its option: letter forms ("A", " A", "**A", " **A", "(A", " (A" and every single token whose stripped text is the letter) and the option's DISPLAYED name in four forms. Paths are evaluated on a prefix trie (KV-cache extension; prefixes below 1e-4 are pruned and their mass is reported). Event masses keep the classes disjoint: a path minus its minimal extensions into another class ("D" minus "D"+"ell" when Dell is an option), and option A's letter paths times 1 − P(space + lowercase word) (the article). The target slot's ABSENT identity (placebo version: the real brand; real version: the substitute) is its own class `identity_leak`, credited to no option. O5 = q_free + (1 − c_free) · q_forced / c_forced: immediate answers at the spec position, the deferred share imputed by the committed answer after "Answer:". O3 (free only) and O4 (forced only) and the imputation-free bounds P_t ∈ [q_free_t, q_free_t + 1 − c_free] are stored per item and summarised. Validated against brute-force path scoring on the smoke model (max |Δq| 7.6e-5; integration test). Replaces `name_mass_*`, `s_target_credit` and the prefilled format check.
- Consistency (spec §7.1, 2% greedy): answers that name an option within `gen_max_new_tokens` are "immediate" (compared with the free argmax); the others are continued to 48 tokens and parsed for a concluding answer ("deferred", compared with the forced argmax, which tests the O5 imputation). Without a concluding cue a deferred answer counts only if it mentions exactly one option; comparisons without a conclusion stay unparsed (= disagreement). The spec warning still uses overall agreement with the O5 argmax; chance levels from the marginal letter frequencies are reported next to every agreement.
- **Spec deviation (§9 cards), matched cards.** Per target, `cards_per_cell` card sets are drawn once and reused in every (evidence, handicap) cell (common random numbers); evidence 0 with `e0_pairs_per_substitute` keeps its own balanced draws. Card set k of target i uses placebo substitute (i + k) mod n_placebo. **Spec deviation (§9 `cards_per_cell: 4`):** the pilot uses `cards_per_cell: 6` = `n_placebo_per_category`, so every target sees EVERY placebo once per cell at e1–e4, as it does at e0 (4 times each). With 4 card sets each target saw a 4-of-6 subset, and placebo-name pull became an entity-specific offset at e1–e4 that e0 does not have (verification simulation with no entity effect: within-category SD of ne_e1..e4 = 0.26 logits vs 0 at e0), which feeds the ladder residual. `build-data` warns when `cards_per_cell` is not a multiple of `n_placebo_per_category`. Cost: 96 instead of 72 pairs per entity. Items carry `card_set`; the schema checks that a card set shows the same options with the same card content in every cell (only visibility and the target's rating may differ). Entity SEs and `n_e{k}` use the placebo substitute as the independent unit (at evidence 0, 24 pairs share 6 substitutes; at e ≥ 1 each card set has its own substitute, and its handicap cells share their cards).
- Manipulation strength: within card sets, the drop in s_target per star of handicap (least squares through the origin over handicap cells vs handicap 0, cluster bootstrap over card sets), per name version. The scale-free **manipulation ratio** = placebo per-star drop / median |ne_e0|; below 0.25 the summary warns that the ladder cannot be read as "evidence overrides reputation". 0.25 is PROVISIONAL and for the PI to confirm.
- Format stability: per version, mean free-position name share and coverage at each evidence level vs evidence 0; a shift > 0.2 is a warning (the ladder would compare different readouts). Mean c_forced < 0.9 is a warning (template or prompt-mode problem); c_free < 0.9 is a notice (share imputed).
- `format-probe` (new command, not a stage): a balanced 40-item dev sample, scored and decoded greedily in full, with prompt tails, per-item coverage, argmaxes and parsed answers. Run it on every new checkpoint before `measure`.
- Probe nulls: `probe.n_null_k` (default 99; must be ≥ 20 so that p < 0.05 is possible; smoke 39) entity-level label shuffles per frame, the SAME shuffles at every layer. Per-layer permutation p = (1 + #null ≥ obs)/(1 + n). Max-T (Westfall–Young) adjusted p per layer: per layer the observed value and the n shuffles are n + 1 exchangeable arrangements, standardised alike by their own mean and SD; the maximum over layers > 0 per arrangement is the null of every layer; adjusted p = #(maxima ≥ z_obs,l)/(n + 1). This is exact (H0 simulation: FWER 0.049–0.054 at 0.05); a first version standardised by the null alone and was anti-conservative (FWER ≈ 0.10 at n = 20). Layers whose values are constant up to rounding (relative SD ≤ 1e-9) get NaN. A check with nothing to test is a "not testable" warning, never a silent pass. A readiness check passes only if effect size AND adjusted p < 0.05 hold at the SAME layer: K capture ≥ 1.2× the null mean, popularity AUC ≥ null mean + 0.05. The 2-SD rule and Bonferroni over layers for these two checks are replaced. Null values are saved in `nulls.npz`. Categories in the within-category permutation are iterated in sorted order (hash order made the tier-transfer p differ between processes).
- **New stage `localize`** (M3 readiness, dev only, spec §7.6 "full" transplants; K/random/complement stay M4): evidence-0 pairs, `localize.pairs_per_entity` per entity, one per placebo substitute in a per-entity random order, at `localize.rotations`. Knock-in (spec direction: placebo run ← real residual) and knock-out (real run ← placebo residual) at `name_last` (spec site), `post_name` (every token after the name up to the free answer position), `final`, and a `band` of `localize.band` consecutive layers at name_last; scored with O5 (the readout continuation is never patched; a patched run whose cache extension fails raises instead of silently re-running unpatched). `localize.layer_stride` must be a multiple of `extract.layer_stride` so that the chosen layer has a K. Entities are (category, brand): Samsung in four categories is four entities. Pooled recovery = Σ ne·δ / Σ ne² (sign-invariant) with a bootstrap CI over entities, and per token-count class of the real name. Across entity means three fits are reported: the identity-line R² (uniform under-recovery and offsets count against it), the offset-invariant R² = 1 − Var(ne − δ)/Var(ne) (what a within-model z of ne − δ still sees) and the correlation. Layer choice: the SPEC rule (highest pooled knock-in recovery at name_last, warning < 0.8) is primary. Pre-registered alternative, reported only, for the PI to decide before M4: the deepest scanned layer with pooled ≥ 0.9 and ≥ 0.8 in every token class with ≥ 3 entities (argmax of a noisy curve is biased upwards). Smoke results are in the review-round entry below.
